# Environment settings — Release 1.2.1

Store real values only in an ignored local .env.local file or the appropriate Vercel environment fields. Keep a separate password-manager entry for TEST and PRODUCTION. The upstream .env.example was cleared intentionally; no values have been restored to it.

| Variable | Visibility | Obtain the value | Configure locally / Vercel |
|---|---|---|---|
| NEXT_PUBLIC_APP_URL | Public origin | The exact browser origin you will open: localhost for local work, copied HTTPS domain from the Vercel test deployment for hosted testing. | Example local http://localhost:3000. Hosted value includes https:// and no path/trailing slash. Must match Supabase redirect allowlist. |
| NEXT_PUBLIC_SUPABASE_URL | Public | Supabase TEST project → Connect or Project Settings → API → Project URL. | TEST project only in Development/Preview. Production project only in Production after approval. |

| SUPABASE_SERVICE_ROLE_KEY | Server secret | Supabase TEST → API Keys → legacy service_role key. It bypasses RLS. | Sensitive server environment field. This code's sync RPC expects service_role behavior; other secret-key formats require runtime verification. |
| INITIAL_ADMIN_DISCORD_ID | Server configuration, identity identifier | Discord → enable Developer Mode → right-click your own user → Copy User ID. | Numeric user ID. Do not use Discord OAuth Client ID or a bot token. |
| MUX_TOKEN_ID | Server credential identifier | Mux dashboard → correct environment → Settings / API Access Tokens; create Video read/write token. | ID paired with the secret below. |
| MUX_TOKEN_SECRET | Server secret | The same Mux token-creation screen; save privately when first shown. | Never expose in NEXT_PUBLIC settings or client code. |
| MUX_SIGNING_KEY_ID | Server signing-key identifier | Mux dashboard → correct environment → Signing Keys. | Must match the environment/asset and private key below. |
| MUX_SIGNING_PRIVATE_KEY | Server private key | Private key from Mux signing-key creation, supplied as base64-encoded PEM. Save privately when returned; public-key retrieval cannot recover it later. | Paste the base64 value into the sensitive server field, not chat/GitHub. Do not add literal quotes/newline escape strings from JSON. Do not double-encode. |
| PLAYBACK_HEARTBEATS_ENABLED | Server release gate | Chosen by the operator, not generated by a provider. | Start false. Set true only for the verified TEST schema after database enable and postflight. Production stays false until separately approved. |

There are TEN variables in this table. Discord Client ID/Secret and database credentials are separate service settings, below; the app does not read them as extra environment variables.

## Values that do NOT go in this application's environment

- Discord OAuth Client ID and Client Secret: Discord Developer Portal → app → OAuth2. Enter privately in Supabase TEST → Authentication → Providers → Discord. No DISCORD_CLIENT_SECRET variable is read by this app. A Discord bot token is not required.
- Database password/connection URL: Supabase TEST Connect panel, or the disposable local stack's local connection details. Needed only for an approved operator/rehearsal, not the Vercel app runtime. No DATABASE_URL variable is read by this code.
- ADP_TEST_DATABASE_URL and ADP_ALLOW_LOCAL_DB_TEST: process-only test-runner inputs for a disposable LOOPBACK database. Never set them in Vercel Production. The PowerShell rehearsal runner sets the URL for its child concurrency test after validating it.
- Vercel access tokens, Supabase management tokens, Mux webhook secrets: not required by the application. No webhook endpoint is used for upload readiness.
- NODE_ENV: managed by Next.js/Vercel. Do not manually set development on a hosted preview; the React harness is intentionally development-only.

## Environment separation

| Use | App URL | Supabase / Discord / Mux | Vercel scope |
|---|---|---|---|
| SQL rehearsal | No website needed | Empty local Supabase base auth database; fake fixture users/assets. No Mux request. | None |
| React queue harness | http://127.0.0.1:4178 | Synthetic media and intercepted responses; no real provider connection. | None |
| Local authenticated testing | http://localhost:3000 | Separate TEST Supabase/Discord/Mux keys; exact local auth callback allowed. | Development only if managed through Vercel, otherwise ignored local file |
| Hosted test deployment | Exact chosen test HTTPS origin | Separate TEST provider resources | Preview, preferably scoped to the intended test branch |
| Future production | Actual member-facing origin | Production resources only after approval | Production |

Each hosted environment needs its own canonical NEXT_PUBLIC_APP_URL. Variables changed in the Vercel dashboard affect a NEW deployment; redeploy to use them. Never populate all scopes with the same production secrets for convenience.
