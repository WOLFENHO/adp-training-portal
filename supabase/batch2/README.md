# QC-003 and QC-013 isolated SQL candidates

These files are **not production migrations**. They have not been executed. The `qc003_deployed_r11_capture.sql` and `qc013_deployed_progress_capture.sql` files are function definitions captured in Astra's Release 121 evidence. The original QC-003 capture with CRLF endings has SHA-256 `f447709ea286384dc4e56e228a265c5e20e6e95112d0c539f7c6a8e8dec8e9ec`; GitHub's LF-normalized text has SHA-256 `191d662205266701233c900493bf0c6de09d9415bce07dec782a491b9172991d`. The QC-013 capture has SHA-256 `da84af59cf3fdba16f884449ffaad59e1f9ec6143a4206672f9ab7fbd32f9bf8`. The surrounding schema, grants, ownership and `r12` wrapper still require a fresh isolated comparison.

QC-003 candidate inserts a single 20-second gap guard into the captured `r11` function after duplicate, sequence and version checks. It stops the active clock and budget and records a rejected receipt. This threshold is provisional. Adversarial tests must simulate 19.999/20.000/20.001-second gaps, retries of identical receipts, old sequence/version, foreground/background buffering, stop/play races, completion after an outage, forged forward seeks and concurrent requests. Assert that no watched interval or verified completion is created on rejection, and that a fresh `play` can resume from confirmed position. Compare `r12` response and progress refresh behavior against the current deployed wrapper. Rollback restores the captured `r11` definition, with ACL and owner fingerprints checked first.

QC-013 candidate defines an atomic video-update-and-audit RPC. It has **no EXECUTE grant** and the application does not call it. Before any grant, test direct Data API access as valid admin, revoked admin, whitelisted member, anonymous and service role; failed audit insert must roll back video update; concurrent publish/metadata changes must obey the video row lock. Confirm unchanged title, publication, progress and audit history after rejected cases. Grant to `authenticated` only after the isolated matrix passes and the authorization functions match current Release 121. The existing `adp_admin_progress` function already performs its audit in one transaction; do not replace it.

Neither candidate should be applied to Production from these files. They require a disposable Release 121 database and current deployed fingerprint/ownership/ACL verification. SQL runtime tests remain blocked without that isolated environment. The local static tests verify capture integrity and candidate scope only.

`qc003_gap_rehearsal.sql` and `qc013_role_matrix_rehearsal.sql` are executable rollback-only fixtures for that disposable environment. Both abort before writes unless the session already has `adp.qc_isolated=confirmed-nonproduction`. The role matrix grants EXECUTE only within its rollback transaction, verifies valid/revoked/member/anonymous access and injects audit failure. The gap fixture checks long/short gaps, duplicate receipt, no evidence on rejection and fresh play. Neither has been run against PostgreSQL. Add concurrent transaction tests and direct Data API requests once the isolated endpoint and identities are available.
